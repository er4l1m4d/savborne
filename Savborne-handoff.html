Savborne build handoff

Savings RPG that runs inside Nimiq Pay. Everything you need to build the mini app: tokens, brand assets, components with React + TypeScript + plain CSS variables, all 30 screens as live recreations with notes, animations and platform rules.

StackReact + TypeScript, plain CSS variables, no UI library.
Design size390 × 844 portrait. Fluid 360–430. Desktop: centered 430px column.
FontsPlus Jakarta Sans (UI, labels, chips, and every figure that updates) + Silkscreen (titles, wordmark, display numerals 20px+).
Style ruleHard pixel edges. No blur, no soft shadows, no gradients. Radius comes from stepped clip-path corners.
Placeholders: item art (8 items) and the character sprites are placeholders in this file. Items and characters are 16×16; UI chrome glyphs and badges are 24×24. Swap in final art keeping each family on its own grid, scaled in WHOLE multiples only (16→48/96, 24→48/72) — 36px and 18px are not whole multiples of either and produce uneven pixels. See the Icon set, UI glyph set, Badge set, Character sprites and Item art groups below.

Pixel art

All art is final and governed by docs/art-bible.md. Grids: nav icons 16×16 Tiny Dungeon tiles snapped to product hues, UI chrome glyphs 24×24 from pixelarticons (MIT, used at their native grid — one exception, check, hand-drawn), characters 16×16 pack-native tiles, items 16×16 (pack tiles + programmatic builds). Whole-pixel scales only (2×–8×), shape-rendering: crispEdges, no rotation. Game-art palette is Kenney's own 27-color set (bible §2) — the four structural darks are interior-outline/shadow only; every asset carries ≥1 color at 3:1 vs the app ground. UI chrome is single-colour currentColor, so it inherits the token of whatever state it is in.

Badge set

Six badges, 24×24, from pixelarticons (MIT © Gerrit Halfmann) at their native grid — the same sourcing decision as the UI glyphs, taken after hand-drawn attempts failed to read. A badge is a flat pictogram, not a roundel and ribbon. Earned, locked and removed are one drawing with a different ramp plus a corner chip, so the states survive grayscale and not just colour: locked carries a minus chip, removed a cross chip, both punched out of the lower right so the pictogram underneath stays legible.

Only the states shown here exist. Three badges are permanent — first_steps, first_blade and steady_hand have no revoke path in computeBadgeActions(), so a "removed" rendering of them would depict a rule the game cannot trigger and is deliberately not drawn. The three revocable ones lose their badge on withdrawal or on falling below the requirement, and the removed state appears on exactly one screen: A_Withdrawal, where it is the only visible cost of taking money out. Display: 48px on the Profile card, 72px in large pixel panels, 24px inline in a leaderboard row — all whole multiples.

Character sprites

All character art is pack-native: one Tiny Dungeon tile per sprite at 16×16, shown here at 6×. The hero has 4 bracket gears (Entry cloth, Bronze plate, Silver steel, Gold gilt via the declared gilt map). The heroine shares every gear body pixel-for-pixel — her head is tile r8c3 clipped to the hero's own outline columns, so only the head differs and the armour never does; the two closed-helm gears keep the helm verbatim and gain four hair pixels under the rim. The AI opponent is rolled from a roster of four rivals per battle, each with its own name; a friend battle always shows a human gear sprite instead.

Idle is a 1px two-frame bob, decoration only — art bible §4 consequence 3 records that it carries no state, because 2px on a 104px sprite measured invisible. Turn state lives in the nameplate border and tag. There are no drawn attack frames — lunge is translateX(24px) over 450ms on steps(6), and impact is a brightness(2.2) flash plus a decaying ±6px shake, both on the same single-pose sprite, which keeps the pack-native rule and costs no extra art.

Components

Every component is built from three CSS ideas: the pixel panel (outline + hard shadow via stacked drop-shadow, corners via clip-path), flat 2px borders, and Silkscreen only for display numerals at 20px and up — every figure that updates is Jakarta with tabular figures. States: default, pressed (sink 4px into the shadow), disabled (off colors, not-allowed), focus (mint 2px outline, 2px offset, never removed).

Pixel panel + button (React + TS)

// PixelPanel.tsx — outline + hard shadow come from drop-shadow, corners from clip-path
import type { ReactNode, CSSProperties } from 'react';
type Tone = 'default' | 'mint' | 'coral' | 'cream' | 'off';
const TONES: Record<Tone, { o: string; s: string; bg: string }> = {
  default: { o: 'var(--sv-line)',  s: 'var(--sv-edge)',  bg: 'var(--sv-surface)' },
  mint:    { o: 'var(--sv-mint)',  s: 'var(--sv-edge)',  bg: 'var(--sv-surface)' },
  coral:   { o: 'var(--sv-coral)', s: 'var(--sv-edge)',  bg: 'var(--sv-warn-fill)' },
  cream:   { o: 'var(--sv-text)',  s: '#8E866E',         bg: 'var(--sv-text)' },
  off:     { o: 'var(--sv-off)',   s: '#1B2624',         bg: 'var(--sv-inset)' },
};
export function PixelPanel({ tone = 'default', children, className = '', style }:
  { tone?: Tone; children: ReactNode; className?: string; style?: CSSProperties }) {
  const t = TONES[tone];
  return (
    <div className="pxw" style={{ '--o': t.o, '--s': t.s } as CSSProperties}>
      <div className={`px ${className}`} style={{ background: t.bg, ...style }}>{children}</div>
    </div>
  );
}

// Button.tsx — primary (coral), secondary (surface), disabled (off)
type BtnProps = React.ButtonHTMLAttributes<HTMLButtonElement> & { variant?: 'primary' | 'secondary' };
export function Button({ variant = 'primary', disabled, children, ...rest }: BtnProps) {
  const tone: Tone = disabled ? 'off' : variant === 'primary' ? 'cream' : 'default';
  const t = TONES[tone];
  const primary = variant === 'primary' && !disabled;
  return (
    <div className="pxw sv-btn" style={{ '--o': primary ? 'var(--sv-text)' : t.o, '--s': primary ? 'var(--sv-coral-edge)' : t.s } as CSSProperties}>
      <button {...rest} disabled={disabled} className={`px sv-btn__face sv-btn--${disabled ? 'off' : variant}`}>{children}</button>
    </div>
  );
}

Check-in sequence (implementation order)

  1. Button → loading (sv-dots), call getBalance.
  2. On success: balance-read count-up (600ms).
  3. +10 XP: xp-pop and xp-fill together (700ms).
  4. If streak changes: streak-tick. If XP crossed a level: level-up after xp-fill ends.
  5. If bracket changed: navigate to Bracket Climb after level-up is dismissed.
  6. Button settles to "Checked in today" (disabled).

Queue every celebratory animation through one FIFO so they never overlap. Skip the queue entirely when reduced motion is on, but still show Level-up and Bracket Climb screens (they carry information).
