# Battle UI redesign - implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Rebuild the Battle batch around the handoff and land the check-in integrity release gate before ranked is exposed.

**Architecture:** `/battle` becomes a three-mode menu with ranked-locked and daily-limit states. Queue, friend-wait, battle and result become their own pushed routes. Shared battle components compose Foundation 2 primitives; a small additive `Meter` carries every progress bar. Battle rules, settlement and matchmaking do not change. The check-in route moves its writes into one `commit_check_in` transaction and is rate-limited.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Tailwind plus `.sv-*` / `.pxw` / `.px`, node:test, the existing CDP render harness.

**Spec:** `docs/superpowers/specs/2026-11-09-battle-ui-design.md`.

**Decision status:** approved 2026-11-09. All recommended options in the review
questions are locked in: additive GET fields plus the cancel route, all
additive primitives, current-rating result tiles, the full check-in gate,
`/battle/friend/[id]`, 20px mode titles, and the Daily Limit Missions link.

**Implementation status:** all tasks are implemented on `battle-ui-redesign`.
See `docs/superpowers/audits/2026-11-05-ui-gap-audit.md` section 13 for the
verification table and the review renders. The live check-in migration and the
real-device pass remain before merge.

## Global constraints

- Branch `battle-ui-redesign` from `main`; one batch, no stacking.
- Use Foundation 2 primitives. The only additive vocabulary is in the spec:
  `Meter`, `Button` sizes `mode`/`item`, `BottomSheet` `headerAction`,
  `ScreenShell` `backLabel`, `RivalArt`, and the battle composition components.
- 12px type floor; 44px targets; 360px no truncated actions or values.
- Coral for the advancing CTA; mint for success/progress/you; off for
  unavailable. The menu follows the handoff card hierarchy, not the generic
  action table.
- Battle and queue API contracts stay. Only additive GET fields and the new
  cancel route are allowed. No battle/queue schema changes.
- The check-in migration is the only schema change in this batch.
- `players.xp` is cumulative; use `xpProgress(level, xp)` if a screen needs it.
- One commit per task; full suite green before each commit.
- Never stage `.env.local`, `AGENTS.md`, InstaBox docs/scripts or machine
  tooling.
- Each task runs `npm test`, `npx tsc --noEmit`, `npm run lint`,
  `npm run build`.
- Each UI task captures 360/390/430 fixture renders and the audit JSON.

- [ ] **Step 3: Write the migration**

Structure:

```sql
-- 1. Deduplicate by UTC day, keeping the earliest reading.
delete from check_ins a
using check_ins b
where a.player_address = b.player_address
  and (a.recorded_at at time zone 'utc')::date
    = (b.recorded_at at time zone 'utc')::date
  and a.id > b.id;

-- 2. Generated UTC day.
alter table check_ins
  add column if not exists utc_date date
  generated always as (((recorded_at at time zone 'utc'))::date) stored;

-- 3. One reading per player per UTC day.
create unique index if not exists check_ins_player_day_uidx
  on check_ins (player_address, utc_date);

-- 4. Backfill the derived count.
update players p
set check_in_count = coalesce(
  (select count(*) from check_ins c where c.player_address = p.address), 0
);

-- 5. Rate-limit table.
create table if not exists api_rate_limits (
  key          text primary key,
  window_start timestamptz not null default now(),
  count        int not null default 0
);
alter table api_rate_limits enable row level security;
revoke all on api_rate_limits from public, anon, authenticated;
grant all on api_rate_limits to service_role;
```

Then `consume_rate_limit` and `commit_check_in` with `security definer
set search_path = public`, execute revoked from public/anon/authenticated and
granted to service_role. `commit_check_in` follows spec 6.2 exactly; it returns
`claimed: false` before any other write when the insert conflicts. `p_player`
keys are authoritative: a present JSON `null` for `bracket` clears it, while an
absent key keeps the current value.

  shields: streak.shields,
  shields_earned: streak.shieldsEarned,
  bracket: newBracket,

const { data: committed } = await db.rpc('commit_check_in', {

```tsx
export function Meter({ value, max, tone = 'mint', height = 14, label }) {
  const pct = Math.max(0, Math.min(100, max > 0 ? (value / max) * 100 : 0))
  return (
    <div
      className="sv-meter"
      style={{ height }}
      role={label ? 'progressbar' : undefined}
      aria-label={label}
      aria-valuemin={label ? 0 : undefined}
      aria-valuemax={label ? max : undefined}
      aria-valuenow={label ? value : undefined}
      aria-hidden={label ? undefined : true}
    >
      <div className="sv-meter__fill" style={{ width: `${pct}%`, background: `var(--${tone})` }} />
    </div>
  )
}
```
