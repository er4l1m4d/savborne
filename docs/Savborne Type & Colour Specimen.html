01 · Colour

The base lifts from #0C1211 to #152420. The real fix is underneath it: the old surface ramp was #151F1D / #0E1716 / #101A18 — three panels roughly 2–3 L* apart, so in practice every card on Home read as the same flat slab and only the border told them apart. The new ramp is ~7 L* per step with rising saturation, so panels separate on their own.

The collision this fixes

In the current file coral does four jobs at once: it is the primary "Check in now" CTA, the enemy health bar, the loss headline, and the "1-week streak" chip — so the thing a player is proudest of is painted in the app's alarm colour. Coral is now restricted to damage and loss. Streaks, level and bracket promotion move to --butter.

If coral is only damage, the primary CTA has to become something. I've rendered §4 with the CTA in --butter (the game convention: amber = "press me / reward"), which makes amber do double duty as both reward-colour and action-colour. The alternative is keeping the CTA coral and accepting that a button shares its hue with the enemy health bar.

05 · What I'd change beyond the two you asked for

Three things fell out of rebuilding the screens. Flagging them here rather than sneaking them in.

  1. Coral stops being the primary button. Right now "Check in now" and the enemy health bar are the same hex. Once coral means only "damage / loss", --butter takes the CTA, which is also the game convention for a reward action. This is the one change you should push back on if you disagree — it moves the app's single most-tapped button.
  2. The streak chip was painted in the alarm colour. "1-week streak" used coral-on-coral-tint, so the thing a player is proudest of read as a warning. It is now butter. Same for the level chip.
  3. Four bracket hues, not one grey metal. Entry / Bronze / Silver / Gold currently share `#C9C1A8` for their outlines, so "Silver" and "Bronze" are indistinguishable at a glance in the header chips and the Items grid. Each bracket now owns a hue, which also makes the Bracket Climb screen legible without reading it.

Two things I'd fix regardless of which font you pick

Self-host, subset, and stop using Google Fonts. Both current families load from fonts.gstatic.com at runtime, which puts a third-party round-trip between a judge opening the app and the app being legible — inside a WebView, on a Nigerian mobile connection, at the moment they are scoring "Functionality, reliability" (45 pts). Subset WOFF2 files served from Vercel with font-display: swap and a preconnect remove that failure mode and cut the payload. If Archivo + Plex is chosen, Plex Mono ships digits and /:±.,NIMXP only — a few KB.

tabular-nums on every figure. §3 shows the failure. HP counters, NIM balances, Elo deltas, the 24-hour challenge countdown and the queue timer all change value in place, so they must not change width in place. This is a two-line CSS fix and it is currently missing.
